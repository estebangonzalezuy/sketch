# Proceso de Szymon (obligatorio en este proyecto)

1. `refs.md`: una nota corta por sketch elegido (qué conservar, qué ignorar) y qué tienen en común.
2. `PLAN.md` antes de codear: cómo se arma, dónde la idea se contradice, la parte más riesgosa, factibilidad.
3. Nombrar el problema técnico más difícil, comparar 2–3 soluciones (calidad, velocidad, esfuerzo, riesgo, costo de cambiar después) y elegir una.
4. `ideas.md`: ideas de features con nota, tamaño y estado (`hecha` / `descartada` / `después`).
5. Antes de un cambio riesgoso, listar qué tiene que seguir igual (ver invariantes en `PLAN.md`).
6. Si el mismo bug sobrevive a dos fixes, no hay tercer parche: se rethink.
